(1) Arsitektur inti
Paper definisikan agent-native saat LLM agents pegang core logic/koordinasi, ubah graph saat runtime bila diizinkan. [Hal 2]
Spesifikasi deklaratif deklarasikan graph agents/tools/data/HITL plus behavioral envelope untuk akses, otonomi, oversight, delegasi, evolusi graph, budget. [Hal 6]
Envelope formal `ES={τ ∈ T: PermittedS(τ)=1}`, runtime wajibkan `τrealized∈ Aθ(c)∩ ES` via block/sanitize/escalate. [Hal 7]
Runtime pisah: agent mesh data-plane mediasi inline `allow/block/sanitize/escalate` dan hasilkan audit events, orchestrator control-plane koordinasi graph divalidasi deterministic reference monitor. [Hal 7-8]
ANR kompilasi YAML versioned dengan JSON Schema jadi graph, bawa otoritas di invocation context, dukung MCP/HTTP tools. Repo: `https://github.com/agent-native-apps/ANR` [Hal 10]

(2) Hasil utama + metrik
Tanpa angka akurasi/latensi/throughput. Hanya audit-derived counts deskriptif. [Hal 11]
Agents pakai Claude Haiku 4.5, 50 runs per spesifikasi, 25 normal + 25 fault-injection expose semua tool schemas sedang authority mesh tetap scoped. [Hal 10-11]
HITL pakai scripted auto-approve backend, tercatat di audit, tanpa nilai judgment/latensi manusia realistis. [Hal 10]
Hasil kualitatif: emergency-response instantiate hazmat coordinator via graph-evolution rule, supply-chain picu ingress/egress mediation, fault-injection hasilkan refused out-of-scope proposals. [Hal 10-11]
Mesh event bawa action type, agents involved, parameters, enforcement decision, policy evaluation results, latency, audit lineage, tanpa agregat numerik di ekstrak. [Hal 8]
Kutipan kapabilitas pihak lain, bukan hasil paper: 25-hour Codex run, multi-day Claude Code workflows. [Hal 2]

(3) Keterbatasan verbatim
1. "The scripted auto-approve backend demonstrates checkpoint interception, decision routing, and audit recording, but does not evaluate realistic human judgment or response latency." [Hal 10]
2. "The table reports these audit-derived counts to characterize the prototype's runtime behavior. They are not a performance or security evaluation." [Hal 11]

(4) Evaluasi K1-K5
K1 trust dinamis: Paper sediakan identitas, scoped permissions, mesh firewall, provenance/trace/audit. [Hal 12-13] Orchestrator konsumsi mesh events/telemetry. [Hal 8] Tanpa skor trust update dinamis. Perubahan envelope wajib spec update otorisasi independen orchestrator. [Hal 8]
K2 konflik tipologi: Paper bedakan agent-native vs agentic. [Hal 2] Orchestrator deterministic/ML-learned/agentic. [Hal 8-9] Outcome mesh allow/block/sanitize/escalate. [Hal 8] Threats: prompt injection, tool poisoning/misuse, inter-agent/compromised-component, state poisoning/cascading failure. [Hal 12] Tanpa tipologi konflik antar-agen. [Hal 12]
K3 biaya-keputusan: Paper cantumkan cost budgets, compute budgets, max execution time, context/memory bounds. [Hal 6] Mesh cek budget terkonsumsi. [Hal 7] Akui LLM reasoning cost/latensi/stochasticity lebih tinggi. [Hal 8] Tanpa fungsi biaya-keputusan kuantitatif. [Hal 6-8]
K4 policy terpadu: Paper satukan permissions, oversight, audit, evolusi graph di spec, enforcement mesh/orchestrator. [Hal 6-8] Adapters protokol independen, mesh tetap mediasi. [Hal 9] Semantics kontekstual open question, butuh ML/LLM evaluator. [Hal 11]
K5 ketahanan: Target kurangi unsafe proposed jadi realized, batasi blast radius via least privilege. [Hal 12-13] ANR single-process, simplified policies, tanpa distributed/hardening/scalability evaluation, tanpa metrik recovery/lolos serangan. [Hal 11]
